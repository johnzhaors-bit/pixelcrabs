# Contributing to PixelCrabs

Thank you for helping improve PixelCrabs.

## Before opening an issue

- Search existing issues first.
- Use the latest public `main` branch.
- Include your operating system, runtime versions and exact reproduction steps.
- Share the smallest safe project or fixture that reproduces the problem.
- Remove API keys, tokens, private source, personal information and model conversations.

## Pull requests

1. Keep each change focused on one problem.
2. Preserve the OpenCode boundary: OpenCode owns the general coding agent, model loop, sessions, tools and source editing.
3. Add or update tests for behavior changes.
4. Document new dependencies, licenses, network access and platform requirements.
5. Do not add hosted PixelCrabs services, private endpoints, commercial resources or credentials.
6. Run the checks documented beside the affected package before requesting review.

Opening a pull request confirms that you have the right to contribute the work under the repository's applicable licenses.

## Development scope

The public project is Web-first. Focused fixes to local preview, visual evidence, provider compatibility, accessibility, documentation and developer experience are welcome. Large architecture changes should begin with an issue so boundaries and upstream compatibility can be discussed first.

## Code of conduct

Be respectful, specific and constructive. Harassment, spam, credential sharing and disclosure of private project content are not accepted.
